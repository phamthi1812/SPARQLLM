# Phase 4: Resource Providers

**Duration:** 2-3 days
**Status:** Ready for implementation
**Dependencies:** Phase 2 complete

## Overview

Implement MCP resource providers for graph inspection. Agents can list and read named graphs generated during query execution. Focus: `store://{session_id}/graphs` resource for multi-turn debugging. Outcome: Optional resource layer for advanced use cases.

## Context & Key Insights

**From research:**
- Resources use URI templates (RFC 6570): `weather://{city}/forecast`
- Resource listing returns metadata (uri, name, description, mimeType)
- Reading resources provides text/blob content for LLM context
- Resources complement tools for read-heavy workflows

**From codebase analysis:**
- Global store accumulates named graphs during query execution
- Each graph has URIRef identifier (uuid or custom)
- Graphs contain PROV-O metadata (start/end times, tool calls)
- `reset_store()` clears all graphs - resource access must happen before cleanup

## Architecture Decisions

### 1. Resource Scope
**Decision:** Session-scoped resources only
- Resources valid during STDIO connection lifetime
- Cleared on connection close (`reset_store()`)
- No persistence across server restarts

**Rationale:** YAGNI - most agents don't need persistence; add if usage patterns emerge

### 2. Resource URI Template
**Decision:** `store://{session_id}/graphs/{graph_id}`
- `session_id`: Connection identifier
- `graph_id`: Named graph URIRef (URL-encoded)

**Example:**
```
store://sess-123/graphs/urn%3Auuid%3A456
store://sess-123/graphs  (list all graphs)
```

**Rationale:** Follows RFC 6570, separates sessions, human-readable

### 3. Resource Listing Strategy
**Decision:** Two listing modes
1. **All graphs**: `store://{session_id}/graphs` - lists all named graphs in store
2. **Single graph**: `store://{session_id}/graphs/{graph_id}` - metadata for specific graph

**Return format:**
```json
{
  "resources": [
    {
      "uri": "store://sess-123/graphs/urn%3Auuid%3A456",
      "name": "LLM extraction result",
      "description": "Generated by ggf:LLM at 2025-11-20T14:30:00Z",
      "mimeType": "application/ld+json"
    }
  ]
}
```

**Rationale:** Enables graph discovery without executing queries

### 4. Resource Reading Format
**Decision:** JSON-LD serialization for graph content
- Read graph, serialize to JSON-LD
- Include PROV-O metadata (provenance triples)
- Compact context for readability

**Rationale:** Consistency with tool output formats

### 5. Session Management
**Decision:** Track session state in server instance
```python
class SparqllmMCPServer:
    def __init__(self, config_file: str):
        self.session_id = f"sess-{uuid.uuid4()}"
        self.session_start = datetime.now()
```

**Rationale:** STDIO connections naturally isolated, session ID for URI templating

### Step 2: Resource Listing Implementation (3-4 hours)
**File:** `SPARQLLM/mcp/resources/store_resource.py`

```python
import logging
from typing import List
from urllib.parse import quote, unquote
from mcp.types import Resource
from rdflib import URIRef
from SPARQLLM.udf.SPARQLLM import store

logger = logging.getLogger("SPARQLLM.mcp.resources")

async def list_store_resources(session_id: str) -> List[Resource]:
    """
    List all named graphs in the store as resources.

    Returns:
        List of Resource objects with metadata
    """

    resources = []

    # Iterate all named graphs
    for context in store.contexts():
        if context.identifier == URIRef("urn:x-rdflib:default"):
            # Skip default graph
            continue

        graph_id = str(context.identifier)
        encoded_graph_id = quote(graph_id, safe='')
        resource_uri = f"store://{session_id}/graphs/{encoded_graph_id}"

        # Extract metadata from graph (PROV-O if available)
        name = extract_graph_name(context)
        description = extract_graph_description(context)

        resources.append(
            Resource(
                uri=resource_uri,
                name=name,
                description=description,
                mimeType="application/ld+json"
            )
        )

    logger.info(f"Listed {len(resources)} graph resources")
    return resources

def extract_graph_name(context) -> str:
    """Extract human-readable name from graph metadata."""
    # Try PROV-O label
    PROV = Namespace("http://www.w3.org/ns/prov#")
    RDFS = Namespace("http://www.w3.org/2000/01/rdf-schema#")

    for _, _, label in context.triples((context.identifier, RDFS.label, None)):
        return str(label)

    # Fallback: graph identifier
    graph_id = str(context.identifier)
    if graph_id.startswith("urn:uuid:"):
        return f"Graph {graph_id[-12:]}"  # Last 12 chars of UUID
    return graph_id

def extract_graph_description(context) -> str:
    """Extract description from PROV-O metadata."""
    PROV = Namespace("http://www.w3.org/ns/prov#")

    # Look for prov:generatedAtTime
    for _, _, timestamp in context.triples((context.identifier, PROV.generatedAtTime, None)):
        return f"Generated at {timestamp}"

    # Look for prov:wasGeneratedBy
    for _, _, activity in context.triples((context.identifier, PROV.wasGeneratedBy, None)):
        # Extract activity name (e.g., ggf:LLM)
        activity_str = str(activity)
        if "ggf" in activity_str or "example.org" in activity_str:
            func_name = activity_str.split("/")[-1].split("#")[-1]
            return f"Generated by {func_name}"

    return "Named graph in store"
```

### Step 3: Resource Reading Implementation (3-4 hours)
**File:** `SPARQLLM/mcp/resources/store_resource.py` (continued)

```python
async def read_store_resource(uri: str, session_id: str) -> str:
    """
    Read graph content as JSON-LD.

    Args:
        uri: Resource URI (e.g., store://sess-123/graphs/urn%3Auuid%3A456)
        session_id: Current session ID

    Returns:
        JSON-LD serialization of graph
    """

    # Parse URI
    if not uri.startswith(f"store://{session_id}/graphs/"):
        raise ValueError(f"Invalid resource URI: {uri}")

    # Extract graph_id
    prefix = f"store://{session_id}/graphs/"
    encoded_graph_id = uri[len(prefix):]
    graph_id = unquote(encoded_graph_id)

    logger.info(f"Reading graph: {graph_id}")

    # Find graph in store
    graph_uri = URIRef(graph_id)
    context = store.get_context(graph_uri)

    if context is None or len(context) == 0:
        raise ValueError(f"Graph not found: {graph_id}")

    # Serialize to JSON-LD
    jsonld_str = context.serialize(format="json-ld", indent=2)

    logger.info(f"Graph serialized ({len(jsonld_str)} bytes)")
    return jsonld_str
```

## Security Considerations

- **Session isolation**: Resources scoped to session ID, no cross-session access
- **URI validation**: Parse and validate URIs, prevent path traversal
- **Size limits**: Large graphs may exceed MCP message limits (future: pagination)
- **Sensitive data**: Graphs may contain API responses - warn users

## Performance Notes

- **Listing overhead**: O(n) graphs, minimal
- **Serialization cost**: JSON-LD serialization ~10-50ms per graph
- **Memory**: Graphs persist in memory until connection close
- **Large graphs**: Consider pagination for >1000 triples (future enhancement)

## Known Limitations

- **No persistence**: Graphs lost on server restart
- **No pagination**: Large graph lists may be unwieldy
- **Single format**: JSON-LD only (no Turtle/N-Triples option)
- **No filtering**: Cannot filter resources by metadata

## Optional Enhancements (Post-MVP)

1. **Persistence**: Save graphs to disk, load on reconnect
2. **Pagination**: `store://{session_id}/graphs?offset=0&limit=10`
3. **Filtering**: `store://{session_id}/graphs?type=llm`
4. **Multiple formats**: Accept header negotiation for Turtle/N-Triples
5. **Graph merging**: `store://{session_id}/merge?graphs=g1,g2`

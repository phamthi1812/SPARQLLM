## Executive Summary

Investigation reveals **significant progress on compiler infrastructure** but **no end-to-end LLM-to-SPARQL translation** yet. Core components exist (physical compiler, cost estimator, explainer, catalog) but critical gap: **no LLM agent generating logical plans from natural language**.

**Current Reality:**
- User must manually write JSON logical plans
- Compiler translates JSON → SPARQL (works)
- Serial killers demo uses manually written SPARQL (not generated)

**Missing for Full Pipeline:**
- LLM agent that takes natural language → JSON logical plan
- Integration of query_generator.py with LLM completion
- End-to-end demo showing: question → plan → SPARQL → results

```python
# demo/simple_pipeline.py
from SPARQLLM.compiler import PhysicalCompiler
from SPARQLLM.catalog.query import load_catalog, get_catalog_summary
import json
import requests

def generate_plan_with_ollama(question, catalog_summary):
    """Use local Ollama to generate logical plan"""
    with open('demo/prompts/plan_system_prompt.txt') as f:
        system_prompt = f.read().replace('{catalog_summary}', catalog_summary)

    prompt = f"{system_prompt}\n\nQuestion: {question}\n\nGenerate a logical plan."

    response = requests.post('http://localhost:11434/api/generate', json={
        'model': 'qwen2.5:3b',
        'prompt': prompt,
        'format': 'json',
        'stream': False
    })

    plan_json = response.json()['response']
    return json.loads(plan_json)

def main():
    question = "List all CSV files in ./data and show their sizes"

    # Generate plan
    catalog = load_catalog()
    catalog_summary = get_catalog_summary()
    plan = generate_plan_with_ollama(question, catalog_summary)

    # Compile
    compiler = PhysicalCompiler()
    sparql = compiler.compile(plan)
```
